# Configuration

Only `status_entity` is required:

```yaml
type: custom:amina-s-card
status_entity: sensor.amina_s_ev_status
```

The card first discovers entities belonging to the status entity's device in Home Assistant's registries. It matches integration, domain, original names, translation keys, unique IDs, and available measurement metadata. Each card resolves its own charger, so MQTT and ZHA chargers can coexist on the same dashboard, including renamed entities.

When metadata is unavailable or a match is ambiguous, the card falls back to a base name derived from the status entity ID. For example, `sensor.amina_s_ev_status` uses `amina_s`. A fallback is rejected when registry information associates it with another device or integration. Without device registry associations, naming remains a best-effort fallback; use overrides for unusual names.

## Integration and entity defaults

The card reads the status entity's integration from Home Assistant's entity registry. ZHA selects ZHA defaults; MQTT is treated as Zigbee2MQTT. Unknown integrations or unavailable registry access use MQTT defaults. Registry snapshots are shared across cards and editors on the same connection, refreshed on the next card update after one minute. Failed requests are retried after 30 seconds on the next update. The card and editor update automatically when discovery completes.

These are the card's expected IDs, not a guarantee of the names generated by your installation. Select different IDs under **Optional override** when necessary.

| Configuration field | MQTT/Zigbee2MQTT default | ZHA default |
| --- | --- | --- |
| `power_entity` | `sensor.<name>_total_active_power` | `sensor.<name>_total_power` |
| `current_entity` | `sensor.<name>_current` | Same |
| `voltage_entity` | `sensor.<name>_voltage` | Same |
| `linkquality_entity` | `sensor.<name>_linkquality` | `sensor.<name>_lqi` |
| `energy_entity` | `sensor.<name>_last_session_energy` | Same |
| `charge_limit_entity` | `number.<name>_charge_limit` | `number.<name>_charge_current_limit` |
| `charger_entity` | `switch.<name>` | Same |
| `alarm_entity` | `binary_sensor.<name>_alarm_active` | Same |
| `alarms_entity` | `sensor.<name>_alarms` | Same |
| `derated_entity` | `binary_sensor.<name>_derated` | Same |

Explicit overrides take precedence. The charger switch and thermal derating entity may need overrides in ZHA.

```yaml
type: custom:amina-s-card
status_entity: sensor.garage_ev_status
charger_entity: switch.garage_charger
current_entity: sensor.garage_amperage
voltage_entity: sensor.garage_voltage
```

Automatic current and voltage discovery also looks for phase B/C entities on the same device, so renamed phase entities can work. Without a registry match, companions use `_phase_b` and `_phase_c` suffixes. Explicit main current or voltage overrides retain the suffix convention: `sensor.garage_amperage` uses `sensor.garage_amperage_phase_b` and `sensor.garage_amperage_phase_c`. No separate phase overrides are needed. See [phase telemetry](phase-telemetry.md).

## Heading and status

The heading uses the status entity's device name, preferring the name you assigned in Home Assistant. Set `title` to override it, or clear an existing title to use the device name. If device information is unavailable, the card falls back to the status entity's friendly name, then its ID.

`sub_status_entity` can select any entity to replace the secondary status text. The main status comes from `status_entity`; separate connected and charging binary sensors are not used. Charging detection expects the status text `Charging` (case-insensitive).

## Missing readings and link quality

Missing, unknown, unavailable, blank, or invalid numeric readings display `-`. Actual zero readings remain visible.

When the main status entity is unavailable, unknown, or missing, the Start/Stop button is hidden and the secondary text reads **Waiting for charger to come online**. Normal controls return when the status becomes available.

Enable LQI/link quality manually in Home Assistant for both integrations. Open the charger's device page, find the diagnostic entity, and enable it in the entity settings. Disabled or absent link quality hides the row. An enabled entity with an unknown or unavailable reading shows `-`.

See [ZHA setup](zha-setup.md) for quirk installation and entity recreation.
